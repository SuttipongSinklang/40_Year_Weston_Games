# Native recording protocol v1

## Legacy foreground step source (not used by native treadmill sessions)

`startSteps()` requests Motion/Activity Recognition permission and starts a foreground-only step source; `stopSteps()` unregisters/stops it. `stepProgress` contains cumulative `{steps: integer}` since source start, or `{error: string}`. Android prefers TYPE_STEP_DETECTOR and falls back to TYPE_STEP_COUNTER with a fresh baseline. iOS queries one second solely to trigger authorization (discarding historical data), then uses CMPedometer updates from current time. No native distance is claimed: JS multiplies deltas by user-configured stride and labels estimates. No GPS, service startup or upload is involved.

Stop on pause/finish/background/destruction; native source totals are not durable. JS checkpoints local treadmill draft and recovers paused. This legacy interface does **not** implement locked-screen capture; native treadmill sessions now use the durable protocol below; existing durable GPS protocol below remains unchanged. Missing sensors/permission/native errors reject or signal failure, never silently turn into manual entries.

WestonRunning is a Capacitor 8 plugin. Native location delivery and durable capture MUST NOT depend on a WebView callback, JavaScript timers, IndexedDB leases, or an open screen. No native GPS upload or network use.

Methods returning the entire durable snapshot: `getState()`, `start()`, `pause()`, `finish()`, `acknowledge({id})`. Event `stateChanged` signals that callers should fetch a snapshot; it need not include coordinates.

Snapshot:
```
{version:1, id: UUID|null, mode:'idle'|'acquiring'|'running'|'paused'|'finished',
 revision: integer, message: string, events: [event, ...]}
```
Events are append-only in order, epoch milliseconds, finite numeric coordinates. A fix event is `{type:'fix', at, timestamp, latitude, longitude, accuracy}`. `at` is the GPS fix timestamp. Pause and finish events are `{type:'pause'|'finish', at}`. Begin/resume have no event: first valid fresh fix starts/resumes active time. Native filters invalid coordinates, accuracy outside 0..40m, timestamps older than 15s or >10s future, and non-increasing GPS timestamps. It rejects fixes before the last transition. JS applies the existing distance/jitter/speed/split filters using each historical event's `at` as engine time, NOT current time.

Start from idle creates an ID and acquires GPS; start from paused acquires for the same ID. Running/acquiring start is idempotent. Start from finished rejects until acknowledged. Pause from running/acquiring stops native GPS and appends a pause (or clears an empty session to idle), including when acquisition was for a previously paused run. Finish stops GPS, appends finish, and keeps all events until acknowledged. Finish with no fix returns idle. Acknowledge only clears a matching finished ID, AFTER JS saves the finished history in IndexedDB. Repeated/stale acknowledgements are harmless and must never clear a different or active session. Snapshot revision increases on state changes. Commands and locations are serialized, and disk persistence precedes reporting success/changed.

An optional `acquisition_at` native field stores the Start/Resume request time. Reject cached fixes with timestamps before that request so first-fix timing can never begin before the user presses Start/Resume. This field is not a route event and JS does not reinterpret historical events using it. Stop/finish clears it. Start accepts a visible Android Activity in STARTED/RESUMED lifecycle; iOS waits for app activation when location authorization returns while the system sheet still makes the app inactive.

Native disk failure stops GPS and reports a recoverable error without deleting the last durable journal. File backups are disabled/excluded. iOS writes remain possible while the device is locked after first unlock. No GPS is requested on plugin load or recovery.

Process restart recovers running/acquiring as paused, at the last recorded event time (never counts process downtime), and records an interruption message. A WebView reload within the SAME live native process does not pause the service. Never automatically restart capture after termination/reboot/force-stop. End GPS on permission revocation, disabled GPS/provider, or persistence failure; retain journal. Temporary unavailable GPS may keep capture awaiting fixes; long gaps are segmented by JS, never fabricated. Cap at 10000 native fix events: append pause, stop GPS, retain route, and explain limit. Coordinates must not appear in logs.

Android: foreground location service started ONLY from a visible activity after foreground precise/coarse permission request, required foreground service + location type permissions, persistent notification with return-to-app and Pause action. START_NOT_STICKY, no reboot receiver. Fine+coarse requested together for modern Android. Handle notification permission Android 13+, GPS disabled, permission denial, start failure. Foreground service continues with screen locked/app background; no ACCESS_BACKGROUND_LOCATION needed for a user-started foreground location session. Stop service on pause/finish/empty/failure. Native Journal is process singleton and synchronized. Service isn't stopped simply because plugin/WebView destroys.

iOS: singleton CLLocationManager delegate and durable journal independent of WebView; location UIBackgroundModes required. When-in-use authorization requested ONLY on explicit start; allowsBackgroundLocationUpdates + showsBackgroundLocationIndicator + activityType fitness + pausesLocationUpdatesAutomatically false. Continuous session started while app is active, accepts authorizedWhenInUse/Always. Do not request Always or relaunch after force-quit. Permission/state changes and manager errors stop safely. Do not stop merely because app enters background.

JS has a separate native tracker; browser tracker remains unchanged. App hides screen wake lock requirement, never calls pause on visibility/pagehide/run-tab navigation, reconciles durable native snapshot on foreground and ticks display only while visible. Completed replay is idempotent, no XP, private local history, current opt-in Supabase backup remains. Browser continues to auto-pause and requires HTTPS.

## Durable native treadmill protocol v1 (2026-10-09)

`getTreadmillState`, `startTreadmill({automatic,stride_m})`, `pauseTreadmill`, `finishTreadmill`, `setTreadmillDistance({distance_m})`, `acknowledgeTreadmill({id})`; `treadmillStateChanged` asks JS to refresh. Snapshot includes version/revision/id/mode/message, epoch started_at/updated_at/ended_at/resumed_at, completed elapsed_ms, cumulative steps, distance_source, stride_m and distance_m. No GPS/route/network. Automatic distance is steps × configured stride; manual distance remains optional alternative. Starts require visible app and reject another occupied outdoor journal (including unsaved finished runs); outdoor Start symmetrically rejects an occupied treadmill journal. JS never auto-pauses native treadmill on lock/background/navigation. Native state is authoritative, cumulative snapshots replace rather than add steps, local history commits before native acknowledgement. A saved result is immutable/idempotent. Old foreground IndexedDB drafts recover paused and must be saved before a new native session.

Android: separate health foreground service, ACTIVITY_RECOGNITION (also requested for manual mode to satisfy health service prerequisites), FOREGROUND_SERVICE_HEALTH, ongoing notification with Pause, no GPS. TYPE_STEP_DETECTOR then counter fallback; reject events predating segment start and duplicate timestamps, reset counter baseline on new service. The counter fallback cannot recover steps before its first baseline reading. Partial CPU wake lock avoids depending on non-wakeup sensor delivery while asleep, released on service destruction; screen stays off but battery consumption is higher. Journal uses AtomicFile in noBackupFilesDir, records each received batch and checkpoints every 15 seconds. No boot restart/START_STICKY. Unexpected termination recovers paused at the latest checkpoint, excluding unknown downtime. OEM/battery restrictions may stop the service; physical tests required.

iOS: singleton CMPedometer and protected atomic file independent of plugin/WebView. The OS motion cache collects while the app is suspended. Active interval start and prior completed interval totals are durable. Query the exact active interval on foreground refresh/pause/finish; replace that interval's cumulative total, preserving prior intervals and excluding paused gaps. Commands serialize async queries; live callbacks are ignored while a command runs. Updates and historical queries never add the same interval twice. No location/audio background workaround. Six-day active interval cap prevents silently accepting a partially expired seven-day cache. After process termination (distinct from ordinary screen locking), recover conservatively paused at last persisted timestamp; force-quit continuity is not claimed. Authorization, query errors and disk failures stop/pause and retain last file. App UI catches up on unlock; continuous screen-off JS/live UI is not promised.

Native build/typechecking and actual phones remain unverified on this Windows host (no Java/Android SDK/Xcode). Browser automatic recording still needs HTTPS and foreground DeviceMotion; it continues to auto-pause on hidden/pagehide/navigation. A localhost website/PWA is not installation of these native services.
