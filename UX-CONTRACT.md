GPS starts only after the runner presses Start and the browser grants location permission. HTTPS is required on a phone; localhost is a secure development exception. Timing begins with the first accurate GPS fix. Pause stops GPS and excludes paused time; resume opens a new route segment. A completed run never awards game-tap XP. Accuracy over 40m, unrealistic speed over 12m/s and small jitter are filtered; GPS gaps over 30 seconds open a separate segment rather than inventing a connecting route. These filters are heuristics, not medical or certified measurements.

Drafts checkpoint every five seconds and on accepted fixes in IndexedDB; a recovered run opens paused and never requests GPS automatically. Transactional leases prevent another tab from overwriting a recording, and finish stores history/removes the draft atomically. Visibility changes, app switching and leaving the run screen pause capture. Browser background/location delivery is not promised; a best-effort screen wake lock is requested during acquisition/running.

The preceding paragraph applies to the browser. The new Capacitor Android/iPhone variant uses native capture with the protocol in mobile/CONTRACT.md. Location requests start only after an explicit Start in a visible app, with precise foreground permission. Native location callbacks persist a private journal independently of WebView/timers. The app doesn't pause for visibility/pagehide or run-tab navigation; on foreground it reconciles capture-time events, excluding real pauses and segmenting GPS gaps. Android uses a location foreground service with notification/Pause action; iOS uses fitness Core Location and location background mode. The native fix cap is 10000 per run, then recording pauses. Neither platform resumes after process termination/reboot/force-stop automatically. Restart recovery pauses at the last recorded event, avoiding counting downtime. In-process WebView reload does not interrupt the native recorder. Native finished data is acknowledged only after local history commits; failures retain the journal and retry under the same UUID. Native storage is excluded from backups; iOS locked writes use completeUntilFirstUserAuthentication. GPS stays local; cloud consent/owner boundaries remain unchanged. Native sharing creates GPX in cache and opens a user-controlled system share sheet; canceled sharing preserves history. Native platform builds and actual phone lockscreen validation are not yet confirmed on this Windows environment.

History shows the 50 latest local runs. Routes are local by default. Each cloud backup requires explicit route-sharing consent and is bound to the current authenticated owner before sending. Failed backups remain local and require explicit retry; no automatic GPS upload occurs on reconnect. Private table weston_runs permits only owner SELECT/INSERT, with no public leaderboard access. GPX export includes GPS coordinates and segmented timestamps, and runs can be exported without a cloud account. OSM road tiles require a separate per-page checkbox that explains the viewed map area is sent to OSM; tiles are never bulk-prefetched or cached for offline use.

Mobile controls remain reachable at 320px width and short landscape heights. The separate workout button is removed at the user’s request. Tapping the character mesh or pressing Enter/Space on the focused game canvas plays; background taps and drags do not score. HUD and quest dock sit outside the playable stage. Health examples and streak are visible on the home screen, in a top strip on regular portrait phones and a side rail on short screens/desktop. The stage reserves separate space on short portrait screens. Sync details remain in a native player-info dialog with Escape dismissal and focus restoration. Other screens are inert when inactive. Hidden tabs never receive keyboard focus. Navigation and loading state reserve stable space.

Progress starts at zero. Each game interaction earns 6 XP; every five interactions complete a mission for 100 XP and 25 game coins. Level and mission state are derived from total workouts in progress.js. Calendar XP shows base XP (6 per interaction), excluding mission bonuses. Health cards, team ranks, and social examples must be explicitly labelled as examples.

Private ledger, derived totals, and activity days are readable only by their authenticated owner. The leaderboard publishes generated player names and game totals. Browser clients cannot edit derived totals. Anonymous browser sessions use Supabase Auth and are tied to that browser; clearing browser data loses access to that anonymous identity. Cross-device sign-in is outside this change.

Local activity is persisted before network delivery. An offline or setup error preserves the queue and exposes a retry action in the persistent status area. UUIDs prevent retrying uncertain requests from counting twice. Success means the server has confirmed the write and its derived total. Cached local progress is never presented as cloud-saved. Game play continues when Supabase is unavailable. A failed 3D load disables play and gives a refresh instruction; storage failures explicitly warn that this page's progress is temporary.

# Live running map

- Both live-view and own-position sharing require explicit session consent. Opening the run screen alone does not connect the live map or publish GPS. Viewing can work without starting a run.
- Only authenticated game players see opted-in positions. The server creates aliases and 60-second expiry; each UID can write/delete only its own point. A scheduled server job purges expired points every minute. Private `weston_runs` routes are never subscribed to or displayed to others.
- Pause, finish, hidden page and switching off sharing withdraw the point after any pending write. Disconnection hides other people's markers and reports an unavailable state. No offline queue of live locations and no automatic re-enabling after errors.
- Screen owner: `running.js`; map/layers owner: `run-map.js`; realtime/controller owner: `run-live.js`; authenticated query owner: `run-live-data.js`. Layout follows the existing page scroller and reserves the fixed running actions/bottom nav.
- Locked-screen native recording remains local. Foreground live publishing resumes only with a fresh GPS sample after returning to the app. Two real phones/network interruptions remain acceptance checks beyond mocked tests.

# Treadmill mode

- Select treadmill before Start. No geolocation requirement. Manual timer works on HTTP; browser automatic sensing requires a secure context and motion consent. Start/Pause/Resume excludes paused time; distance defaults to an explicit phone-step estimate with configurable stride (0.30–2 m). Automatic mode requires no manual distance; optional manual console distance (0–200 km, explicit zero permitted) is required before Finish only in manual mode. Missing/invalid distance focuses the field and explains recovery. No GPX/live location/splits are invented.
- Save commits a normal private local history record with `activity=treadmill`. Recovery pauses rather than counting app downtime. Activity switches are blocked until the current run is saved; native outdoor recording remains separate. Browser treadmill auto-pauses on hidden/pagehide/tab leave. Native treadmill uses a durable recorder and never pauses merely for lock/background/navigation; iPhone reconciles cached steps on foreground.
- Optional private cloud backup preserves activity and contains summary distance/time, measurement source and optional steps/stride, with empty route/splits. Existing Auth setup dependency applies only to cloud; home recording works offline. Native locked-screen behavior requires an installed build and physical acceptance testing; browser remains foreground-only. Hardware pairing is not implemented.


# Current running persistence and installation — 2026-10-09

- This section supersedes the optional backup/GPX descriptions above. All newly finished runs commit share=true and cloud_state=pending atomically before deleting the browser draft or acknowledging the native journal. The queue scans all pending records, binds the first authenticated owner durably before delivery and never rebinds another owner's record. UUID insert-on-conflict plus an own-row confirmation makes uncertain writes retryable.
- No GPX or manual backup controls. History automatically refreshes the authenticated owner's cloud runs. Online status is confirmed/pending, with automatic reconnect/reload/foreground/30-second retries. An offline device cannot upload immediately; retain data until delivery succeeds. Existing private local history remains local.
- Explicit GPS pauses/resumes retain numbered events. A pause location is the last accepted fix, and a resume location is the first new accepted fix. Unlocated events are listed without fake map coordinates. Dropout segments are not manual pauses. Treadmill sessions have no fabricated GPS/map.
- Anonymous Sign-Ins was enabled by the owner and verified with successful real sign-in and REST write/read/idempotency on 2026-10-09. Existing weston_runs owner RLS applies to events; security advisor reports zero notices. Test rows were removed.
- Website-only requirement: no APK/download UI. Hidden/page visibility and in-site menu changes checkpoint without automatically pausing the workout. The existing watch/motion listener stays registered, but GPS/step delivery while hidden is controlled by the browser. Time is reconstructed from active timestamps; missing steps are not invented. Fresh GPS resumes into a separate segment after a >30-second gap, with no invented connecting distance; summary discloses missing intervals. Reload/discard/real page exit recovers as paused at the durable checkpoint. Permission denial or lease takeover still stops capture. This does not promise background GPS or sensor delivery on Android/iPhone browsers.
