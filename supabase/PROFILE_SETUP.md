# ตั้งค่าข้อมูลสุขภาพและหัวตัวละคร

โปรเจกต์เป้าหมาย: `jlweqxpkqgnjcwcgisfj` เท่านั้น

1. MCP `weston_supabase` ต้องใช้บัญชีที่มีสิทธิ์เข้าถึงโปรเจกต์นี้ การติดตั้งปลั๊กอินอย่างเดียวไม่เปลี่ยนสิทธิ์บัญชี
2. ตรวจตารางเดิมก่อนใช้ `profile-onboarding.sql` ผ่าน MCP migration หรือ SQL Editor ของโปรเจกต์เป้าหมาย ไฟล์นี้สร้าง `weston_health_profiles` และ bucket ส่วนตัว `weston-private-avatars` พร้อม RLS ของผู้เล่นแต่ละคน
3. ตรวจด้วยบัญชีผู้เล่นสองคน: อ่าน/แก้ข้อมูลและดาวน์โหลดรูปของอีกคนต้องไม่ได้ ส่วนผู้เล่นเจ้าของต้อง insert, select, update และ upload/download รูปตนเองได้
4. เปิดเว็บใหม่หรือกด “เชื่อมต่ออีกครั้ง” ในข้อมูลผู้เล่น ตรวจสถานะบันทึกออนไลน์และโหลดกลับจาก Supabase

สถานะวันที่ 2026-10-09: เชื่อมโปรเจกต์ผ่าน `weston_supabase` และใช้ migration `private_health_profile_onboarding` สำเร็จแล้ว ตารางข้อมูลสุขภาพและพื้นที่รูปส่วนตัวพร้อมใช้งาน ตรวจสิทธิ์แบบ rollback ผ่าน `tests/profile-database.sql` และทดสอบ API จริงผ่าน `tests/profile-online-smoke.mjs` ครบ 8 รายการ รวมบันทึก/โหลดกลับและป้องกันผู้เล่นคนอื่นเข้าถึงข้อมูล ล้างข้อมูล รูป และบัญชีทดสอบแล้ว ดูรายละเอียดที่ `tests/artifacts/profile-verification.md`

ข้อมูลในเว็บผูกกับ Supabase anonymous session ปัจจุบัน การล้างข้อมูลเบราว์เซอร์ทำให้ anonymous session หาย; ระบบนี้ยังไม่มีการผูกบัญชีเพื่อคืนข้อมูลข้ามเครื่อง

รูปที่เก็บเป็น JPEG ที่ครอบบนอุปกรณ์แล้ว ไม่เก็บไฟล์ต้นฉบับและไม่ส่งรูปเข้า AI ภายนอก ใช้ MediaPipe Face Landmarker ที่รวมไว้ในเว็บวิเคราะห์จุดบนใบหน้าบนอุปกรณ์ แล้วสร้างหัวการ์ตูนเป็นรูปทรง 3D พร้อมตา จมูก ปาก หูและผม ไม่มีแผ่นภาพหรือ texture รูปถ่ายบนหัว ชุดและลำตัวใช้ geometry เดิม รูปทรงและสีปรับจากรูปหน้า แต่ทรงผมใช้แบบมาตรฐาน และความเหมือนเป็นการประมาณ ไม่ใช่การสแกนใบหน้าแบบสมบูรณ์ รูปที่ตรวจไม่พบใบหน้าคนหรือมีหลายใบหน้าจะไม่ผ่านการสร้างหัว การเปลี่ยนรูปไม่ได้ลบรูปเวอร์ชันก่อนหน้าออกจาก private Storage; ต้องกำหนดการเก็บรักษา/ลบเวอร์ชันก่อนเผยแพร่ใช้งานจริง

เป้าหมาย BODY150 ยังรอตารางอ้างอิง Body Fat และนิยามกล้ามเนื้อที่ยืนยันแล้ว ฟอร์มบันทึกข้อมูลได้โดยไม่สร้างเป้าหมายหรือคะแนนสุขภาพจากตารางจำลอง
